# VFS491 2.0.2 engineering record

## Objective

2.0.2 is a recognition-observability release. The 2.0.1 data showed a poor genuine-verification result (3 matches across 12 visible verify attempts) and substantial per-frame metric variation. Those facts justify better measurement, but do not identify whether the dominant cause is acquisition, image orientation/polarity, ridge extraction, enrollment-template quality, finger presentation or matcher behavior.

The release adds a stable key from the libfprint TOD claim to each frame event and a local tool that records each `fprintd-verify` outcome with the capture events from the same journal time window.

## Runtime changes

Each successful TOD device claim receives a random UUID. Each capture request increments a claim-local sequence. The backend writes machine-readable journal messages:

- `type=capture_start`: start of one capture request.
- `type=frame`: completed and validated grayscale frame plus derived metrics.
- `type=capture_error`: broker status and elapsed time for a failed capture.

The identity is the pair `(claim_id, capture)`. It disambiguates repeated captures inside a single fprintd claim and claims from separate verification attempts. It is not a fingerprint identifier.

Frame events contain dimensions, payload byte count, elapsed time, intensity percentiles, mean/standard deviation, entropy, dark/bright proportions, row/column variation and horizontal/vertical gradients. Pixel bytes, templates, minutiae, username, raw command output and finger images are not written by the study tool.

## Verification-study utility

Run one attempt per command. Keep the study serial: do not run other `fprintd-verify`, enrollment or competing fprintd capture operations during the same journal interval, or unrelated claim events could be included in the time-window record.

```bash
vfs491-verify-study --finger right-index-finger --class genuine
vfs491-verify-study --finger right-index-finger --class different-finger
```

It runs the normal `fprintd-verify` command interactively, obtains the matching `fprintd.service` journal interval, parses `VFS491_EVENT` records and appends one JSON object to `~/VFS491-verify-study.jsonl`. The file is created with mode `0600`. The account name is passed to fprintd but is not stored in the record.

Use `--class genuine` for an enrolled-finger trial and `--class different-finger` when physically presenting a different finger against that same enrolled template. The class is a human-supplied test label, not an identity decision. Use one run per attempt. If journal access is denied, the verification result is still recorded but `journal_error` is populated and capture correlation is incomplete. Grant the account access to the system journal or collect journal data through an administrator-controlled workflow before interpreting the dataset.

A single verification operation may produce more than one capture event because the existing driver permits bounded recovery for ordinary acquisition errors. Retain all events in that record; do not assume one verify call always equals one frame.

## Recognition invariants retained

- `bz3_threshold` remains 40.
- Enrollment remains one stage, matching the archived Validity reference.
- `FPI_IMAGE_COLORS_INVERTED | FPI_IMAGE_V_FLIPPED` remains unchanged.
- No crop, rotate, mirror, resize, intensity normalization, contrast enhancement, adaptive threshold, image rejection heuristic or pixel rewrite is introduced.
- The frame parser and bounded acquisition retry / poisoned-session behavior remain unchanged.

These invariants prevent a diagnostic release from silently modifying the recognition algorithm or making false accepts easier. 2.0.2 does not claim higher recognition accuracy.

## Controlled test design

1. Confirm the device is healthy and the enrolled finger label is correct.
2. Run at least 20 separate enrolled-finger attempts through `vfs491-verify-study`.
3. Run at least 10 attempts using a different finger; all must reject.
4. Repeat the sequence after one fresh enrollment, keeping the first dataset intact.
5. Group the JSONL records by result and compare the associated frame metric distributions and elapsed times. Keep failed acquisition events separate from `no-match` results.
6. Correlate any outliers with swipe conditions and the raw system journal locally. Do not upload raw fingerprint pixels or templates.

Do not change the threshold, enrollment stage count, polarity/orientation flags or add a frame-quality gate based on this dataset alone. Any future recognition change must demonstrate a genuine-accept improvement while preserving different-finger rejection, using a larger controlled sample and the exact target libfprint build.

## Build and release state

The archive is a source candidate. The container can run source-level and Python tests, but it cannot certify the target libfprint TOD ABI or physical VFS491 behavior. Build and package on the HP EliteBook 8470p against its installed `1.94.7+tod1` core/TOD pair, then run the hardware acceptance plan. Do not replace an installed driver with this candidate until that build and the current package staging checks pass.
